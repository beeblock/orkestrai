# Native agent access, task-scoped waits and terminal launch settings

## Confirmed causes

1. Native node layout, reusable project Shell creation and reversible note archival were not exposed through the agent bridge. Agents resorted to Computer to manipulate Orkestrai itself, which incorrectly made those tasks depend on desktop-control setup.
2. Leader supervision treated the latest `waiting_input`, `waiting_permission` or `blocked` activity as a workspace-wide veto even when it named just one task. Idle specialist recovery had the same broad suppression.
3. The saved Codex launch arguments still selected `gpt-6-astra` while the exact leader transcript recorded a confirmed `/model` change to `gpt-6.1-sol`. Cold resume reapplied the stale node override. The new setting had been confirmed without a subsequent model turn, so reading only `turn_context` would also miss it.

Read-only diagnosis did not alter project tasks, provider configuration, OS consent or credentials.

## Implemented contracts

- Native Canvas commands follow route → controller → shared-schema FormRequest → DTO → service → ORM repository. The agent endpoints support any workspace and both leader/specialist actors, not a project-specific exception.
- `canvas_list` returns a paginated, allowlisted inventory and layout revisions, never raw payloads, environment or grants. `canvas_update_layout` validates every target and revision before an atomic batch; exact retries are safe, concurrent changes require rereading.
- `shell_create` confines cwd to the project or an approved repository alias, reuses a caller-supplied UUID on retry and stores an automatic startup command. The private process-wide PTY singleton submits startup once per live Shell, including off-screen nodes. Renderer remounts do not repeat it. Uncertain submissions are never replayed. Submission is not server-health evidence. Commands must not contain credentials.
- `note_archive` and `note_restore` use existing soft archival and retain note content, task references and edges.
- Mutations authenticate both the workspace token and the actor's private live-PTY token, require its assigned active task and preserve explicit policies/suspension. Credentials stay in process memory and are absent from node summaries and audit input. Computer permissions are not involved.
- Task-scoped waits and unanswered task questions exclude their card, not independent executable assignments. Unscoped legacy questions retain conservative attribution. Fully blocked/completed boards remain silent. Existing reminder budgets, provider completion checks, human-draft protections, quota limits and uncertain-delivery guards are preserved.
- Codex cold restore and terminal reload read the exact saved session and launch cwd, including Floor/WSL context and configured Codex homes. Bounded asynchronous reads select the newest valid provider settings/context record, including `thread_settings_applied` with no later turn. Only model/effort overrides are replaced; unrelated arguments remain intact. No global provider config is written.
- The provisioned skill, leader contract and portable instructions make a direct owner task standing authorization for its normal delivery and require continuing independent cards. Explicit owner restrictions, configured gates, actual OS consent and stops remain authoritative.

## Regression prevention

- Feature tests exercise internal layout with Computer disabled, atomic cross-workspace rejection, stale revisions, secret-free inventory, reversible archival, Shell idempotency/confinement and single startup across concurrent service copies. Authenticated controller tests exercise both agent roles and reject spoofed identity.
- Runtime tests exercise three task-specific waits, fully blocked leader cards, new work after an old unscoped wait and specialist continuation on a different card.
- Session tests cover confirmed `/model` without another turn, newest-record precedence, invalid/prose records, effort reset, exact cwd/session isolation, native and POSIX transcript roots, and persisted restoration in two workspaces.
- CLI/MCP tests exercise actual route payloads against the backend schema. Every native Canvas command must have tested agent dispatch; every advertised MCP id must be unique and have a dispatcher. This checks registration, not successful execution of every capability on every platform.
- Production E2E fixtures check off-screen Core startup plus Canvas remount and persisted cold model restoration. They isolate data and provider homes and do not launch a paid model.
- The unconfirmed-reminder fixture uses the actual `Transcript confirmation timed out` error and awaits its initial drain before advancing time. Its previous generic `Not confirmed` error meant a retryable transport failure, not an uncertain submission, and raced the asynchronous dispatcher under load. Production uncertain-submission guards are not relaxed.
- The long-leader-briefing fixture waits for a raw-mode PTY before delivery, matching agent TUIs. Canonical macOS `/bin/cat` previously truncated the flattened briefing at `MAX_CANON` and emitted BEL. All task-content assertions remain in place; a readiness signal replaces the startup race, not a larger timeout or a weaker assertion.
- Root `AGENTS.md` now requires agent-access contracts, tests and docs with every future workspace feature. The in-app docs and guided tour are synchronized in all three languages.

## Boundaries

This is not a claim that all existing UI functionality has been exhaustively audited, that model output cannot stall, or that all provider terminal menus are persisted. Terminal selection restoration here targets Codex, the provider in the reported failure. Existing configured gates and real macOS Computer permission failures remain separate; no OS grants are fabricated. A registration test cannot prove task throughput. Measured live deliveries and installed-build verification must be reported separately from source tests.

## October 11: incomplete Shell lifecycle and Portal host defaults

The next-day read-only Moedex audit found both reported cards still `doing`. The leader recorded `blocked` for Shell configuration at 21:40 UTC and `waiting_permission` for City host `[::1]` and simulated login/OTP at 21:41 UTC on October 10. These are not successful deliveries, despite the previous local installation and passing creation-only fixtures.

- Confirmed omission: the bridge only offered `shell_create`; retrying that operation with another command correctly refused a different configuration. It had no edit operation. `shell_update` now accepts revision-checked title/cwd/startup changes and preserves unrelated settings, command ids/order and live processes. Legacy single-command bridge Shells are supported; ambiguous legacy command ownership is rejected rather than guessed.
- `canvas_list` returns separate opaque Shell configuration revisions and live session ids, without exposing commands/env. Revisions use a process-private HMAC, avoiding an offline guessing oracle for private configuration values. `shell_restart` is a distinct, explicit operation bound to the current configuration and live session; retries cannot terminate the replacement. It does not kill by port or stop sibling nodes. Startup remains once per owned PTY and is not health evidence.
- Confirmed Portal cause: bridge creation automatically persisted the first hostname as an allowlist. Both server and Electron also added the current hostname to the list, implicitly restricting empty lists and weakening explicit lists. New bridge Portals now start with no host restriction; empty means HTTP(S) navigation without URL credentials. Explicit nonempty lists remain exact, including redirects. Existing stored lists are not silently widened because their provenance is not safely distinguishable from later owner settings.
- Confirmed UI validation bug: saving host settings discarded bracketed IPv6. Shared hostname validation now retains `[::1]`, rejects URL/port/credential inputs and prevents an invalid form submission from silently weakening a list. The existing generated control gains inline localized feedback and focus; this was informed by the interface-review skill.
- CLI/MCP dispatcher parity and feature regressions now cover edit and restart, not creation alone. Provisioned leader instructions describe correction and reevaluating old missing-tool blockers after an app update. No new periodic reminder loop is added.
- The remaining login/OTP and 49 journey acceptances are not claimed resolved by these infrastructure changes. No real authentication challenge is bypassed and no Moedex source, task status or acceptance evidence is fabricated.
